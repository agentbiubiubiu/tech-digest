第 102 期：Agent 的下一份产出，应该是证据

第 102 期 · 2026年9月19日，星期六

Agent 的下一阶段价值，不是更快地产生答案，而是把验证、约束和回读做成可重复的工程资产。

✨ 本期亮点：Trail of Bits 用六个月构建审计工具链，产出95个机器校验证明并找到测试漏掉的问题 · 9项工具与方法：3项今天可试，6项需要安装、账号或硬件条件 · Claude Code 开始兼容 AGENTS.md，但云端渠道仍有覆盖边界 · 本地模型、浏览器 Agent 与代码审查都按证据和权限而非演示效果判断

来源：Trail of Bits；数字与结果均来自该团队对单个 Miden 审计项目的复盘。

🔥 主故事

不是让 Agent 直接审代码，而是先让它造一座验证工厂

六个月、超过一百个 AI 生成提交、九十五个机器校验的证明——最反常识的是，最大的收益并非那台反编译器本身。

Trail of Bits 接手 Miden 零知识虚拟机审计时，面对的是自定义低层汇编语言和几乎空白的开发工具生态。团队让 Agent 构建 LSP、反编译器、静态分析引擎和 Lean 执行器模型，再用这些工具辅助人工审计。

核心冲突直接让 Agent 找漏洞更快，但难以证明完整性；先建专用工具和形式化模型投入更大，却能把结论变成可重复检查的证据。
转折点团队发现，投入最大的反编译器真正留下的资产不是完整反编译流程，而是其内部中间表示和分析框架；这些组件可继续支撑静态分析。
为什么是现在编码 Agent 已把一次性工具和形式化脚手架的生产成本压低，但模型输出仍不够可靠，价值正在从“直接答案”转向“帮助建立验证系统”。
对团队的启发为高风险变更定义证据包，把测试、静态分析、日志与回读作为 Agent 的交付物；先提高可验证性，再扩大权限和并行度。

6个月准备95个机器校验证明100+个AI生成提交2个单测漏掉的边界缺陷

我的判断：这不是“AI 已经会做安全审计”的证明，而是一个更稳健的工程信号：高风险场景应优先让 Agent 扩大验证带宽。只有规格可表达、结果可独立复核、长期复用价值足够高时，六个月的前置投入才成立。

先让 Agent 造尺子，再让它量代码。

来源：blog.trailofbits.com

🛠️ 工具推荐

Agent 工作流方法可试

验证工具优先法

先让 Agent 构建测试、分析器、模型或回读脚本，再让它处理高风险变更。

适合你的环节：安全审计、核心交易逻辑、复杂迁移与回归验证

今天怎么试：从一个高风险任务中挑出一项可自动判定的证据，例如属性测试、接口回读或静态规则，让现有 Agent 先只交付这项验证资产。

边界：适合高风险、可形式化且会重复发生的任务；一次性小改动可能不值得前置投入，Trail of Bits 案例历时六个月。

采用判断：优先借鉴规则，不新增平台；先在一个真实任务上验证证据包是否降低复核时间。

当前做法：当前已有 Codex 和测试/审查流程，但具体项目是否已有统一证据包未知，基线更新于2026-09-17。

新增收益：把 Agent 产出从“代码与说明”扩展为可重复运行的证据，减少人工凭感觉验收。

验证标准：同一任务比较现有流程与证据优先流程；成功条件是缺陷检出或复核时间改善，且误报、构建时间和权限范围不得恶化。

Agent 工作流方法可试

无记忆同事交接法

把仓库和任务写成“明天醒来完全失忆的同事”也能继续的状态。

适合你的环节：长任务续跑、跨线程交接、自动化恢复与失败点记录

今天怎么试：选一项跨天任务，只保留目标、已完成阶段、证据路径、失败点和下一步，次日从该文件恢复。

边界：这是访谈中的个人方法，不是经过对照实验的效率结论；过度记录会增加维护成本。

采用判断：今天可试，先限定在一个自动化；若状态维护成本超过恢复收益则放弃。

当前做法：本日报已使用 run-state 恢复，但其他项目是否普遍采用未知。

新增收益：给现有状态文件增加“证据路径与不得重复的外部写入”，直接降低续跑重复动作风险。

验证标准：用一次中断续跑验证：不得重复抓取、写笔记或发布，恢复后产物与连续执行一致。

审查方法方法可试

风险分级代码审查法

按变更风险决定阅读、测试与自动化验证深度，而不是统一要求逐行审查或完全不读。

适合你的环节：PR 审查、AI 生成代码验收与发布前门禁

今天怎么试：给下一个 PR 标注低、中、高风险，并为每级写明必读文件、必跑测试和人工确认点。

边界：文章是 GitHub 播客对热门观点的拆解，不是实验；风险级别仍需结合业务、权限和可回滚性定义。

采用判断：立即试用方法，不依赖新工具；若团队无法对风险等级达成一致，先从发布权限和资金影响两项硬指标开始。

当前做法：当前已有代码审查和静态验证习惯，但仓库级风险分级规则是否统一未知。

新增收益：把“要不要读代码”的争论转成可执行的验收矩阵，减少低风险浪费与高风险漏检。

验证标准：连续抽取3个不同风险PR，对照缺陷发现、审查耗时和漏跑门禁；高风险项不得减少人工复核。

Claude Code 网关升级验收清单

边界：仅适用于经代理或网关接入 Claude Code 的环境；当前是否使用及版本未知。

🧩 本期概念库

1. 验证带宽

一句话解释：团队能以测试、模型、分析器和回读同时验证多少变更，而不只是多少代码被生成。

为什么重要：当生成速度超过人工审查速度，瓶颈会从实现转向证据生产与复核。

团队应用：把测试、日志、截图和接口状态作为 Agent 交付契约，按风险增加验证深度。

2. 工具先于结论

一句话解释：面对陌生系统，先建立语言工具、抽象表示和可执行规则，再判断代码是否正确。

为什么重要：它把一次性的模型判断变成可复跑、可审计、可积累的工程资产。

团队应用：复杂迁移或交易逻辑审查前，先补 lint、属性测试、对账脚本或状态机模型。

3. 风险分级审查

一句话解释：根据影响、权限、可回滚性和证据强度分配不同的人审与自动审查成本。

为什么重要：统一的“全读”或“全信”都会浪费资源或扩大漏检。

团队应用：把认证、资金、发布和数据迁移设为高风险，要求人工确认与独立回读；低风险样式改动可轻量验收。

4. 指令兼容层

一句话解释：用共享文件承载跨 Agent 规则，同时保留各运行时的优先级和能力差异。

为什么重要：文件名收敛不等于语义完全一致，加载顺序和渠道支持仍会改变行为。

团队应用：为 AGENTS.md 建最小读取测试，并记录各客户端版本、目录规则与覆盖关系。

🎙️ 播客提纲

展开口播稿

先造验证工具，再让 Agent 找问题

一个安全团队为了审计一套陌生的零知识虚拟机，没有先让 Agent 扫代码，而是花六个月让它写语言服务器、反编译器、静态分析器和形式化模型。听起来像绕远路，结果却找到单元测试漏掉的缺陷，还产出了九十五个机器校验的证明。今天真正值得理解的，不是 Agent 又能写多少代码，而是它能不能把“我觉得对”变成可复查的证据。

主故事：验证能力才是产能

Trail of Bits 在审计 Miden 虚拟机时面对的是一门低层、陌生、几乎没有开发工具的汇编语言。团队让 Agent 连续数月构建 LSP、反编译器、静态分析框架和 Lean 模型。九十五个机器校验的证明覆盖了核心库的一大部分，并暴露了两处原有单元测试没有捕获的边界问题；静态分析还帮助定位了一个未经校验的证明者输入。关键转折是，最费力的反编译器最终最有价值的并非完整反编译结果，而是过程中沉淀的中间表示和分析框架。我的判断是：Agent 的高价值不只在直接给答案，而在把原本“贵到不值得做”的专用验证设施降到可承受范围。成立条件也很严格：任务高风险、规格足够明确、结果能由证明、测试或独立工具复核。六个月投入和单一项目案例，不能被写成普遍的短期效率收益。

快讯一：项目指令开始收敛

Claude Code 2.1.277 在没有 CLAUDE.md 时会读取 AGENTS.md。对同时使用多种编码 Agent 的仓库，这是减少重复维护的一步，但并不是完全统一：该能力当时还未覆盖 Bedrock、Vertex 和 Foundry。最小验证不是相信发布说明，而是在一个临时仓库放入互相可区分的指令，确认实际客户端读到了哪一份。

快讯二：本地模型要看完成率和等待时间一起变化

JetBrains 的 Junie Local 公开了一个很有用的取舍：旧模型推理开启后完成更多任务，但大约慢四倍；新混合模型在内部一百个任务上从三十四个提升到三十七个。三个任务的增量不足以单独证明值得切换，尤其还依赖指定 Mac 硬件和本地运行环境。真正的验证应同时记录完成率、端到端耗时、人工返工和隐私收益。

快讯三：给 Agent 浏览器，也等于给它新的权限面

Cline 展示了 Jev 浏览器插件：配置网关密钥后，Agent 可以在后台启动 Chrome 完成网页任务。它把“代码生成”延伸到网页操作，但也扩大了 Cookie、登录态、下载和误操作的风险面。若要尝试，只在隔离浏览器配置和无生产权限账号中跑一个可回滚任务，并核对每一步产生的外部状态。

团队行动：先定义证据包

今天最值得采取的动作不是再装一个工具，而是选一个高风险、重复发生的研发任务，先写出证据包：输入固定、基线结果、自动测试、关键日志、截图或接口回读，以及不得退步的条件。然后再让现有 Agent 执行。若它只能给出看似合理的代码，却不能交付这些证据，就不应获得更大的权限。工具层面，Flutter 官方插件和 Claude 的 AGENTS.md 支持都值得做小范围兼容性验证，但先不要全仓切换。

今天的一句话：先把验证做成工具，再把工具交给 Agent。速度是结果，证据才是控制面。

✅ 对团队的启发

1

给高风险 Agent 任务定义统一证据包：测试、日志、截图或接口回读至少命中两类，缺证据不算完成。

2

把 AGENTS.md 兼容视为迁移功能：按客户端、版本、目录层级和云渠道做读取验收，再减少重复指令文件。

3

评价本地或云端编码模型时同时记录完成率、端到端耗时、人工返工和权限边界，禁止只比单一榜单。

4

浏览器 Agent 默认使用隔离配置和最小权限账号，任何外部写入都要求结果回读。
