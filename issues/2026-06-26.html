第 48 期：Agent 开始把工作量从对话，改写成工时

第 48 期 · 2026年6月26日，星期五

✨ 本期亮点：OpenAI 披露 Codex 在 OpenAI 内部占 99.8% weekly output tokens · 80.6% 个人用户发起过超过 30 分钟人类工作量的 Codex 请求 · Vercel AI SDK 7 把 Agent 开发、运行、Harness、观测做成生产栈 · GitHub Actions 支持 job 内并行 step · Cloudflare Workflows 支持 saga rollback · npm 高影响账号敏感变更后 72 小时只读 · HF Jobs 一条命令起 vLLM 私有端点 · IBM 发布 0.7nm/7 Å nanostack 芯片技术 · Vesuvius Challenge 首次完整读出一卷赫库兰尼姆卷轴

Vercel AI SDK 7 官方图：Agent 正从一次模型调用，升级为带审批、持久化、观测、Harness 和沙箱的生产运行时。
🎯 本期核心判断：Agent 的竞争焦点正在从“能不能回答”转向“能不能被授权、持久执行、观察、评审并跨职能交付长任务”；组织真正要管理的单位会从 chat message 变成 agent-hours。
⏱ 本期建议阅读顺序
先看主故事：OpenAI 如何把 Codex 使用从 token 统计推进到“人类工时阈值”。
再看三条冲突趋势：Agent 工时化、生产治理、硬件与能源约束。
最后看工具和文章：Vercel AI SDK 7、HF Jobs、GitHub Actions、Cloudflare Rollbacks，以及“工具对话疲劳”。

🔥 主故事

从 chat message 到 agent-hours：OpenAI 开始量化数字劳动力

一个人一天只有 24 小时，但 OpenAI 说 Codex 的重度用户已经能在一天里并行生成 60 小时以上的 Agent 工作。

OpenAI 6 月 25 日发布经济研究文章，用 Codex 数据描述 Agent 对工作的影响。文章把 Agentic AI 的单位从单次互动改写为“delegated, long-horizon tasks”：它们能独立运行数分钟到数小时，调用工具、与环境交互并迭代完成目标。OpenAI 披露，截至 2025 年 8 月，普通 OpenAI 员工花在 Codex 上的 token 还不到 10%；到 2026 年，工程、Legal、Finance、Recruiting 等部门都把 Codex 作为主要工作 AI 工具。

核心冲突聊天时代管理的是问题和答案；Agent 时代管理的是被授权出去的工作量、上下文、工具权限、预算和结果质量。效率上去了，但失控面也跟着变大。
转折点OpenAI 不再只展示模型能做什么，而是开始用“超过 30 分钟、1 小时、8 小时人类工作量”的阈值衡量 Agent 请求。到 2026 年 5 月，80.6% 的抽样个人用户至少发起过一次超过 30 分钟人类工作量的 Codex 请求，70.2% 发起过超过 1 小时的请求，25.6% 发起过超过 8 小时的请求。
为什么现在发生Vercel 同日发布 AI SDK 7，把 tool approvals、durable WorkflowAgent、timeouts、sandbox、OpenTelemetry、Harness adapters 等生产能力打包；GitHub Actions 支持 step 并行，Cloudflare Workflows 补 saga rollbacks，HF Jobs 一条命令起私有 vLLM 端点。工具链正在围绕“长时间、可恢复、可审计、可回滚”的 Agent 工作形态重组。
对团队的启发团队不要只统计“用了多少次 AI”或“花了多少 token”。更重要的是建立 agent-hours、任务类型、权限边界、审批点、失败回滚、人工验收和成本归属。Agent 一旦变成工作单位，就应该像 CI、任务队列和生产作业一样被治理。

80.6% >30 分钟70.2% >1 小时25.6% >8 小时99.8% weekly output tokens99 分位 >60 小时/天非开发组织用户 189x

我的判断：这份研究最重要的不是“Codex 很受欢迎”，而是它把 Agent 从工具体验变成了劳动计量问题。未来组织的 AI 成熟度，可能不是看有多少人打开聊天窗口，而是看多少高价值任务能被安全地委派、并行、恢复、验收和复盘。

Agent 时代，最该被管理的不是提示词，而是被委派出去的工时。

来源：openai.com

⚡ 冲突趋势

对话次数 vs Agent 工时

过去看 AI 使用率，现在要看被委派出去的可恢复、可验收工作量。

OpenAI 的 Codex 数据把 AI 使用从“问答次数”推进到“长任务工时”，这是组织治理口径的变化。

openai.com · vercel.com

自主执行 vs 生产治理

Agent 越能长时间执行，越需要审批、沙箱、超时、回滚和审计。

Vercel、GitHub、Cloudflare 同日更新的不是炫技能力，而是把 Agent 放进生产系统要补的护栏。

vercel.com · github.blog · blog.cloudflare.com

AI 规模化 vs 物理与供应链约束

Agent 工时增长会继续推高计算需求，但电力、芯片密度和安全供应链都在同时收紧。

IBM 的 0.7nm nanostack、Un-0 的物理计算实验和 npm 的高影响账号保护，都在提醒：AI 规模化不是纯软件问题。

newsroom.ibm.com · unconv.ai · github.blog

📰 科技动态

1、IBM 发布 0.7nm / 7 Å nanostack：把芯片缩放推到原子尺度叙事 announced

IBM 宣称推出世界首个 sub-1 nm 芯片技术，采用 0.7nm / 7 Å transistor architecture 和 3D nanostack。官方称指甲盖大小芯片可容纳近 1000 亿晶体管，密度接近 2021 年 2nm 芯片的两倍，并预计相对 2nm 节点最高性能提升 50% 或能效提升 70%，SRAM scaling 提升 40%。

2、Cloudflare Workflows 支持 saga rollbacks：长流程失败后要能反向补偿 confirmed

Cloudflare Workflows 现在支持 saga-style rollbacks，开发者可以在每个 step.do() 旁边声明失败后的补偿逻辑。Cloudflare 用跨银行转账举例：如果后续步骤失败，系统不应只重试，还要能按相反顺序撤销已经完成的副作用。

3、GitHub Actions 支持 job 内并行 step：CI 终于不用只靠 shell & 硬撑 confirmed

GitHub Actions 新增 background、wait/wait-all、cancel 和 parallel 关键字，让同一个 job 内的 step 可以并发执行，同时保留独立日志和执行控制。典型场景包括多个 build 并行、后台服务启动后运行依赖测试、上传遥测时继续打包。

4、npm 为高影响账号加 72 小时只读保护，拦住“改邮箱后发恶意包”路径 confirmed

npm 对负责热门包的 high-impact accounts 增加预防性保护：一旦检测到邮箱变更或使用 2FA recovery code，账号会进入 72 小时只读状态，并向旧邮箱发出提醒。期间包仍可安装下载，但发布、token 管理、可见性和组织成员变更会暂停。

5、Bunny DNS 取消查询费：500 个 zone 内免费，smart records 也不加价 confirmed

Bunny 宣布 Bunny DNS 不再按查询收费，单账号最多 500 个 domain 免费托管，无查询上限、无 per-request billing，smart records 和 health monitoring 也包含在内；平台仍有标准 $1/月最低消费。

🤖 AI 相关

1、Vercel AI SDK 7：Agent 开发栈从模型调用升级为生产运行时 confirmed

Vercel 发布 AI SDK 7，称其每周下载量超过 1600 万。新版把 Agent 能力分成 develop/run/integrate/observe/beyond text 五层：reasoning control、typed runtime context、scoped tool context、tool approvals、durable WorkflowAgent、timeouts、sandbox、OpenTelemetry、HarnessAgent 以及语音/图像/视频支持。

2、Vercel 把“产品设计判断”写成 repo 内 skill，给 Agent 上审美课 confirmed

Vercel 公开 product-design 系统：把已接受的产品决策像代码一样保存在仓库里，由 agent skill、linters 和 evidence-intake workflow 组成。Skill 会按 shape/implement/review/copy/harden 路由到 product-judgment、interface-quality、copy、patterns 等 canonical references，避免 Agent 在 UI/UX 上凭感觉扩散。

3、HF Jobs 一条命令起 vLLM 私有端点：实验型推理服务继续变轻 confirmed

Hugging Face 展示用 hf jobs run 直接启动 vLLM OpenAI-compatible endpoint：指定 GPU flavor、暴露 8000 端口、运行 Qwen3-4B，即可用 OpenAI client 或 curl 调用。文章还给出 2×H200 运行 Qwen3.5-122B-A10B、通过 Pi 接成 coding-agent backend 的示例。

4、Un-0：用耦合振荡器模拟物理计算，挑战 AI 能耗边界 announced

Unconventional AI 发布 Un-0，一个由耦合振荡器模拟系统驱动的图像生成模型。官方称其在 ImageNet 64×64 上达到 FID 6.74，并开放权重、训练、评估和 ablation 代码；目标是探索未来约 1000x 能效提升的物理计算 substrate。

5、Reuters：Anthropic 指控 Alibaba 对 Claude 做大规模 distillation reported

Reuters 报道称，Anthropic 在一封提交给美国参议院银行委员会的信中指控 Alibaba 相关操作者对 Claude 能力进行非法提取。报道提到 2026-04-22 至 2026-06-05 期间，相关活动通过近 25,000 个欺诈账号产生超过 2,880 万次 exchanges；Alibaba 未立即回应 Reuters 请求。

📝 文章推荐

1、The Exhaustion of Talking to a Tool

这篇文章抓住了很多 AI 工具用户没说出口的疲惫：好工具应该像身体延伸，但 LLM 工具常常要求你对话、解释、协商、安抚，相当于把“社交脑力”花在工具上。它不是反 AI，而是提醒我们：工具设计不能把人持续推入谈判模式。

2、You can’t unit test for taste

作者做跑步路线应用时，本以为 AI 会成为功能核心，最后发现 AI 只能当辅助：地理数据、DuckDB/Parquet 管道、人工审美和产品判断一起决定结果。它和 Vercel 的 product-design skill 指向同一件事：品味很难被单测，但可以被证据、规则和人工判断约束。

3、Lies, Damn Lies and Database Benchmarks

QuestDB 用 ClickBench 做例子提醒：数据库 Benchmark 看起来像奥运会，实际更像一边跑步一边吹口哨的奇怪比赛。不同数据库类别、数据布局、查询形态和调参方式会让“谁最快”变成一个上下文问题。

4、The Doorman Fallacy In Action

一顿早午餐里的 QR 菜单、停车短信和拆账流程，把“技术替代人类岗位没有副作用”的 Doorman Fallacy 讲得很具体。它适合放进 Agent 时代思考：不是每个自动化都减少摩擦，有些只是把服务成本转嫁给用户注意力。

🧩 本期概念库

1. Agent-hours

一句话解释：把 Agent 工作从“消息数/调用数”转成类似人类工时的委派工作量，用来衡量长任务、并行执行和组织产出。
背景来源：OpenAI Codex economic research
为什么重要：它把 AI 使用率统计推进到生产治理指标。
团队应用场景：为内部 Agent 任务记录估算工时、实际耗时、人工验收时间和业务价值。

2. Durable Agent Execution

一句话解释：Agent 执行状态能跨部署、重启、中断和延迟审批保持，并可恢复继续运行。
背景来源：Vercel AI SDK 7 WorkflowAgent
为什么重要：长任务 Agent 不可能只靠单进程内存活着。
团队应用场景：把关键 Agent 流程设计成可恢复作业，而不是一次性脚本。

3. Saga Rollback

一句话解释：长事务里每个步骤配套补偿动作，失败时按相反顺序撤销已完成副作用。
背景来源：Cloudflare Workflows
为什么重要：很多业务操作跨外部系统，不能依赖传统数据库事务。
团队应用场景：交易、提现、发券、通知和外部 API 流程都应设计补偿路径。

4. Scoped Tool Context

一句话解释：工具只拿到自己需要的配置和密钥，而不是共享整个 Agent 上下文。
背景来源：Vercel AI SDK 7
为什么重要：第三方工具越多，最小权限越重要。
团队应用场景：给内部 Agent 工具定义 context schema，避免工具间共享不必要 secret。

5. Model Distillation Attack

一句话解释：用强模型输出训练弱模型或竞争模型，从而复制能力的攻击或灰色竞争手段。
背景来源：Reuters reported Anthropic/Alibaba dispute
为什么重要：模型能力会成为可被提取、监控和争议化的资产。
团队应用场景：对高价值模型 API 增加异常批量调用、账号集群和输出模式监控。
