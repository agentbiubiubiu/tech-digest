第 66 期：AI 能把不可能的重写变便宜，但不能替团队定义什么叫成功

第 66 期 · 2026年7月27日，星期一

✨ 本期亮点：AI 辅助 Tree-sitter 重写成为主故事：首次快约 20% 的不可解释版本被全部回滚 · 作者自测最终解析吞吐 +29.74%、端到端 CPU 约 -22.2%、峰值内存约 +29.8% · Lean + LLM 约 20 分钟完成性质证明但玩具程序慢约 10 倍 · SQLite WAL 只读短连接出现 7/6400 次锁 · Drone-Bench 五项串联成功率仍为 0% · Secure MCP Tunnel、Impeccable、Port Zero、Buzz 进入开发工具雷达

ast-grep 作者自测：Rust 核心的原始解析吞吐约高 29.74%，完整 outline 工作负载的用户态 CPU 时间约低 22.2%，但峰值内存约高 29.8%。
🎯 本期核心判断：Coding Agent 正在把过去只有大团队敢做的重写和形式化验证变成个人可尝试的工程，但可信提效仍取决于人类收缩范围、保留行为基线，并同时测正确性、端到端性能、内存和可解释性。
⏱ 本期建议阅读顺序
先看主故事：为什么一次 AI 重写要先经历全部回滚，才得到可信的性能提升。
再看证明与可靠性：Lean 自动证明、SQLite WAL 只读锁、Drone-Bench 端到端归零。
最后看可直接试用的前端验收、端口管理、Agent 日志、MCP 内网接入和工作流工具。

🔥 主故事

AI 重写 Tree-sitter：第一次快 20% 却会崩，全部回滚后才得到可信的 22%

一段代码跑得快了约 20%，为什么作者反而把它全部删掉？因为它已经快到没人能解释，还会毫无预警地段错误。

ast-grep 的性能瓶颈长期落在 Tree-sitter：每个文件都必须先解析成语法树。对一个人来说，重写成熟 C 运行时意味着 ABI、生成语法、外部扫描器、错误恢复和庞大测试生态，过去足以让计划一直停在愿望清单。Coding Agent 把实验成本降下来后，作者让 ChatGPT 分阶段把核心迁到 Rust，并以现有测试和兼容性作为答案钥匙。

核心冲突AI 可以快速制造一个 Benchmark 更漂亮的版本，却不能自动保证代码可解释、内存可接受、边界正确。第一次优化达到作者要求的约 20% 后，层层叠加的生成代码难以理解，并出现段错误；作者没有继续打补丁，而是把优化全部回滚。
转折点转折不是换了更强模型，而是换了问题定义。作者移除 Agent 完整文件快照场景不需要的增量旧树复用和原生 Wasm 语法加载，先把 C 风格 Rust 整理成能局部推理的结构，再逐层分析词法、栈、子树生命周期和端到端路径。最终结果不再声称一比一替代上游 Tree-sitter，而是一套明确服务 ast-grep 与 Coding Agent 工作负载的更窄运行时。
为什么现在发生我的判断：Coding Agent 最重要的经济变化，是让高风险实验的第一次尝试变便宜。过去个人不会启动的语言迁移、解析器改写和证明任务，现在可以快速得到可运行版本；但实验是否能进入产品，仍要靠范围选择、测试基线、性能剖析和人工可理解性。
对团队的启发把 Agent 驱动重构分成四道门：先冻结行为基线和兼容性测试；明确目标工作负载与非目标；同时记录端到端延迟、CPU、内存、崩溃和输出等价性；任何人无法解释的优化不得因为 Benchmark 变好而合入。

第一次优化约快 20%，因不可读和段错误全部回滚作者自测原始解析吞吐 +29.74%完整 ast-grep outline 用户态 CPU 时间 1.233 秒降至 0.960 秒，约 -22.2%同一完整工作负载峰值 RSS 26.52 MiB 升至 34.43 MiB，约 +29.8%TypeScript 压力语料峰值内存 91.2 MiB，早期版本曾超过 1 GiB

我的判断：标题里的「30%」只对应作者自测的解析吞吐，不是整个应用都快 30%。端到端约 22.2% 的 CPU 改善伴随约 29.8% 的峰值内存增加，而且结果尚未独立复现。真正值得复制的不是让 AI 重写核心库，而是作者愿意丢掉一个数字更漂亮、工程上却不可信的版本。

AI 把不可能的重写变便宜，工程纪律决定它是产品还是一次漂亮的事故。

📰 科技动态

1、SQLite 三天没写数据，SELECT 仍会锁：WAL 也要匹配连接生命周期 reported

数据库几乎不写入，却由大量短生命周期进程反复只读打开。作者发现 WAL 连接仍需更新 -shm 与空的 -wal 协调文件，打开和关闭窗口可能触发 SQLITE_BUSY；在 64 个进程各跑 100 轮的典型复现里，零超时 WAL 出现 7 次锁错误，增加 1 秒 busy timeout 或改回 DELETE journal 后为 0。所以呢？「WAL 更适合并发」必须附带连接池和负载模型。

2、GrapheneOS 的 duress PIN 进入联邦刑案：安全功能不能替法庭证明意图 reported

一部 Pixel 在机场搜查中输入密码后重启并丢失数据，检方据此指控 Samuel Tunick 为阻止扣押而故意销毁内容；辩方则主张询问和无令状搜查侵犯权利。法院文件确认案件编号 1:25-CR-499，但故意毁证仍是控方指控，辩方主张也尚未裁定。所以呢？防胁迫、自动擦除和审计文案一旦进入司法场景，功能与使用意图必须严格分开。

3、欧盟隐私组织要「杀死 Cookie Banner」：这是倡议，不是已通过法规 announced

如果浏览器已经知道用户拒绝追踪，为什么每个网站还要再问一次？欧洲民间组织推动在 Digital Omnibus 讨论中采用机器可读隐私信号，减少逐站 cookie banner；它们同时反对改革包中其他可能削弱隐私权的部分。页面明确写着成员国和欧洲议会尚未决定立场，所以这是一项倡议，不是已生效监管。

4、LLM Token 转售链浮出水面：最高 97.8% 标称折扣仍只是调查者报告 reported

一个没有硬消费上限的公开 AI 端点，可能不只被刷账单，还会被接进转售市场。Simon Willison 转述 Vectoral 调查：部分中继服务汇聚 API Key 后低价转售，调查者称 10 个高流量站点合计约 360 万月访问、最高标称折扣 97.8%。密钥来源可能包括试用滥用、未保护机器人、盗刷和拒付，但规模和来源尚未被模型厂商或执法机构独立确认。

🤖 AI 相关

1、Lean + LLM 把高成本证明压到约 20 分钟，但玩具解压器仍慢 10 倍 reported

形式化证明过去贵得惊人：Adam Langley 引用 seL4 复盘，证明时间约是设计实现的 10 倍，证明代码超过 C 代码 20 倍。他用 Lean 写 Zstandard 解压器，并报告多个 LLM 能在约 20 分钟内自动完成 FSE 表性质证明，证明通过类型检查且无 sorry。反转也很明确：玩具解压器比命令行 zstd 慢约 10 倍，verified assembly 实验还因内存和规模问题卡住。

2、OpenAI Secure MCP Tunnel：私有 MCP 无需开放入站公网，但仍经过受控中继 confirmed

企业接 MCP 的老问题是「要不要给内网工具开洞」。OpenAI 的 Secure MCP Tunnel 让内网开源客户端主动建立出站 HTTPS 长轮询，接收请求并转发给批准的本地服务；它支持流式响应、OAuth 发现、自定义 CA、代理与 MCP 侧 mTLS。这里的准确表述是「客户侧无需开放入站公网」，不是没有 OpenAI 中继，也不是免做安全审查。

3、Drone-Bench：15 个模型最佳单次可过 4 项，五项串联成功率仍为 0% reported

模型不是不会飞，而是会把墙看成门。Drone-Bench 把室内无人机跟踪拆成重建、定位、导航、检测和跟随五项；评测方对 15 个模型各跑 10 次，部分优秀单次运行可过 4 项，但没有任何模型通过全部五项，端到端成功率仍为 0%。所以呢？评估 Agent 不能把最佳单项分数相加，错误会沿任务链逐层放大。

4、旧搜索 Benchmark 被刷到 90% 后，美团用 762 万实体重新出题 reported

当旧考卷被刷到 90% 以上，继续庆祝分数已经没有意义。美团团队用覆盖 762 万维基实体的知识图谱构造 LoHoSearch，经人工核验形成 544 题；作者报告 GPT-5.5 得分 34.74%，DeepSeek-V4-Flash 从 BrowseComp 的 58.84% 降到 10.02%。这不是独立结论，而是 Benchmark 作者自报结果；值得团队拿走的是评测饱和后应重做问题空间。

📝 文章推荐

1、托管 Agent 的大脑和手应该分开：会话持久，容器可以短命

长任务 Agent 最怕跑到一半容器消失。Anthropic 把无状态 harness、持久事件日志、隔离沙箱和凭证代理拆开，让会话不绑定某个容器，执行环境可重建，沙箱也拿不到长期 OAuth 与 Git 凭证。官方自报首 token 延迟 p50 约降 60%、p95 超过 90%，但样本和外部复现未披露。

2、设计不是消灭妥协，而是公开选择自己不擅长什么

「无妥协产品」听起来很强，实际往往只是拒绝承认选择。Steph Ango 认为，任何方案一旦被选中，就同时放弃其他选项；好设计不是平均满足所有人，而是针对明确受众选择值得承担的弱点。它给需求评审一个更诚实的问题：我们是否主动选对了缺点？

3、不学 Fusion 360，先让本地 Qwen 和 Claude 接力做钟表外壳

一个不喜欢 CAD 的系统管理员，只想做自动校时数字钟，项目却一路扩展到 systemd、Python 显示程序和 LLM 操作 Fusion 360。本地 Qwen 一次接近完成、另一次仍犯错，随后 Claude 补完设计。这不是「AI 一键 CAD」的 Benchmark，而是一个不会机械设计的人用 MCP 跨过工具门槛的具体案例。

4、Starship Flight 13 的方法论：完整软着陆也不能掩盖助推器硬着水

Flight 13 部署 20 颗测试星、完成在轨发动机重启和 Starship 完整软着陆，团队终于获得较完整的隔热瓦返回数据；与此同时，Super Heavy 部分发动机未能在着陆燃烧中重启，助推器仍硬着水。下一次尝试塔架回收只是 Elon Musk 的条件式表述，前提是数据复核没有问题。

🛠️ 工具推荐

Impeccable P0 Web/UI

把 23 个设计命令与 60 条确定性检测规则封装为跨 Codex、Claude Code、Cursor 等工具的 Skill。适合给 Agent 生成前端增加品牌上下文和可重复视觉检查；设计改善是作者主张，先在非核心页面配合截图验收。

Port Zero P0 Web/Agent

让服务监听 port 0，由系统分配端口，再映射到稳定的 *.portzero.local 域名。适合多 worktree、多 Agent 和并行前端环境，避免反复抢占 3000/5173；采用前验证证书、容器和网络边界。

PGSimCity P1 Backend

用 14 个交互场景把 PostgreSQL 连接、进程和存储路径画成 3D 城市。适合后台培训和故障讨论；作者明确标为未经审查的早期原型，不能替代 PostgreSQL 官方文档。

Claude Code Guard P1 Agent Safety

用 PreToolUse hook 在 Agent 写入 .env、密钥或迁移目录前返回 exit 2，把文字提醒变成执行门禁。它故意 fail-open 且不拦 Bash，适合作为护栏示例，不是完整权限系统。

Vercel WAF for Blob P1 Web/Backend

无需改 Blob URL 或业务代码，在 CDN 第一字节前执行 deny、challenge、rate limit、redirect 与 log。当前是 beta，共享规则和服务端 challenge 可能误伤，应先用 log 模式验证。

Vercel Workflow Extended Duration P1 Backend

Pro/Enterprise 的 Workflow step beta 可从 800 秒提升到 1800 秒，Hobby 仍为 300 秒。适合长 Agent 和批处理，但必须继续设计检查点、幂等、重试与超时恢复。

Go Analysis Framework P1 Backend/Go

Go 官方模块化静态分析框架，可复用 inspector、fact 与诊断机制构建团队规则。适合把业务级不变量变成可在 CI 重复执行的 analyzer，而不是继续依赖人工 Review 记忆。

Decker P2 PC/Web

继承 HyperCard 思路的轻量互动文档与应用平台，可在 Web、桌面和命令行使用。适合快速做内部交互原型、教学工具和可分享演示，不适合作为复杂生产前端替代品。

Agent Collaboration

Buzz

Block 的实验项目，用 Nostr 签名事件统一人、Agent、Git、CI 和审批记录，并支持三层 BYOH harness。适合研究 Agent 身份与审计架构；README 明确有尚在接线的能力，先做只读评估。

Multi-model API

aisuite

以 OpenAI 风格接口统一多家模型，再叠加 Agents、Toolkits 与 MCP。适合做模型对照和轻量适配，但生产仍需逐提供方验证参数、流式工具调用、错误语义与回退。

Remote Coding

Codex Remote engineering guide

把手机端定位成远程工程控制面：先锁定主机、工作区、分支和 worktree，再排队、引导和审查任务。最值得迁移的是「环境先于提示词，diff 先于合并」的操作纪律。

🧩 本期概念库

1. Workload-Scoped Rewrite

一句话解释：不追求一比一替换成熟系统，而是明确目标负载、保留可观察兼容性，并删除目标场景不需要的能力。
背景来源：ast-grep Tree-sitter Rust rewrite
为什么重要：缩小范围能让个人与 Agent 承担过去不现实的核心重写，同时减少不可验证表面积。
团队应用场景：重构前写目标负载、兼容面和非目标清单；Benchmark 必须覆盖实际调用路径。

2. Benchmark Triangulation

一句话解释：同时看局部吞吐、端到端时间、内存、崩溃率和输出等价性，避免单一指标制造虚假胜利。
背景来源：ast-grep parser and outline measurements
为什么重要：AI 很擅长按一个数字优化，也可能把成本转移到可维护性或其他资源。
团队应用场景：每次性能 PR 固定至少一个业务端到端指标和一个资源副作用指标。

3. Proof Automation

一句话解释：让 LLM 搜索证明结构，再由小型可信内核检查证明是否成立；生成者可以不可信，验证器必须确定。
背景来源：Lean Zstandard experiment
为什么重要：它可能降低形式化验证的人力门槛，但不能保证命题正确、程序高性能或证明可扩展。
团队应用场景：从协议解析、金额状态机或关键不变量的小范围性质开始，不直接改写整套生产系统。

4. Joint Task Success

一句话解释：连续任务的成功率取决于各阶段联合表现，单项最好成绩不能替代完整链路结果。
背景来源：Drone-Bench
为什么重要：Agent 的感知、导航、工具调用和恢复误差会逐步累积。
团队应用场景：移动端、浏览器和交易 Agent 测完整用户路径，并单独记录失败恢复能力。

5. Protocol-Level Consent

一句话解释：由浏览器或用户代理以机器可读信号表达隐私偏好，而不是每个网站重复弹窗询问。
背景来源：Kill the Cookie Banner initiative
为什么重要：它可能改变 Consent UI、数据默认值和合规责任的分配。
团队应用场景：前端把 consent 状态机与视觉弹窗解耦，为浏览器级信号和区域差异保留适配层。

✅ 对团队的启发

1Agent 驱动核心重写先冻结行为基线，再写目标负载与非目标；无法解释的优化即使更快也不合入。

2性能报告至少同时给端到端时间、CPU、内存、崩溃和输出等价性；Benchmark 必须标注作者自测或独立复现。

3多进程 SQLite、浏览器/移动端 Agent 和长任务都补完整链路压力测试，不用单项成功代替联合成功。

4模型 API 凭证默认硬限额、分环境、可即时吊销；预算告警不能替代消费上限。

5内网 MCP 和远程 Agent 采用出站通道、目标白名单、凭证代理与执行审计，连接更方便不能扩大默认权限。
