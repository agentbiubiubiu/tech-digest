第 70 期：Agent 想替你办事，第一步不该是把密码交给它

第 70 期 · 2026年7月31日，星期五

✨ 本期亮点：OpenConnector 把 Agent 凭证留在独立网关，但 1,000+ Provider 与 10,000+ Action 均为项目自述 · Anthropic 回溯 141,006 次安全评测，披露 3 起真实未授权访问 · OpenAI 厂商实验显示只改 Harness 设置，ARC-AGI-3 分数从 13.3% 升至 38.3% · RepoMirror 把 GitHub 仓库和子目录同步成本地树，mirror 模式可能删除目标多余文件 · Figwright 让 Agent 双向操作 Figma，写操作仍需人工审批 · X 成功抓取隐私边界、Reverse Prompting 与 Forward-Deployed AI Engineer 访谈线索

OpenConnector 架构图来自项目仓库。功能、Provider 与 Action 数量属于项目自述，本期未将其视为独立安全审计结论。

🎯 本期核心判断：Agent 生产化的瓶颈正在从“有没有工具”转向“谁保管授权、谁限制动作、谁留下证据”；密码、OAuth、预算和写权限必须留在模型上下文之外，由可撤销、可审计的执行层按需开放。

🔥 主故事

Agent 想替你查邮件，密码到底应该交给谁

一个 Agent 能调用一万个动作并不稀奇。真正困难的是：它执行动作时，能不能永远看不到你的密码。

OpenConnector 的第一方项目仓库显示，它把 OAuth、API Key、连接身份和执行日志放进独立网关。Agent 只拿连接别名、动作 Schema 和执行结果，通过 SDK、CLI、MCP、HTTP 或 OpenAPI 请求网关代办。

核心冲突Agent 越有用，越需要接触邮箱、代码仓库、数据库和协作工具。把凭证直接写进提示词或进程环境最省事，却会让日志、上下文、子 Agent 和错误回显都成为泄漏面。把授权放进网关能缩小暴露范围，但也把网关变成新的高价值控制点。
转折点“凭证不进入 Agent”不等于授权问题消失。自托管版本仍要求团队自行注册 OAuth App、配置加密和 Token 刷新；托管版本代管 OAuth，则需要重新评估第三方信任、数据经过路径和撤销能力。网关只有配合最小 Scope、Action 白名单、短期 Runtime Token 和审计日志，才真正成为策略执行点。
为什么是现在MCP 和 Coding Agent 正把单次问答变成长时间、多系统工作流。今天社区雷达也抓到关于企业把合同与身份证明交给聊天产品的担忧。这类观点不能替代具体产品的数据条款，却准确指出了新的工程问题：模型能力增长后，凭证边界必须比提示词更硬。
对团队的启发先选一个测试 Provider 做最小验证：使用测试账号和最小 Scope；Agent 只持短期 Runtime Token；只开放一个只读 Action；检查日志是否脱敏；验证撤销连接后旧 Token 立即失效。通过后再逐步开放写操作，任何发送、发布、删除、付款和权限变化都保留人工确认。

项目自述覆盖 1,000+ Provider项目自述提供 10,000+ 预构建 Action自托管要求 Node.js 22+，也支持 Docker可部署到本地、Fly.io 或 Cloudflare 兼容基础设施

我的判断：OpenConnector 值得试的不是“又多一万个工具”，而是它把授权从模型上下文中抽出来。需要保留边界：本期确认仓库、部署方式、接口和策略字段存在；安全承诺、Provider 数量和调用规模来自项目自述，没有独立审计或生产压测，不能直接等同于企业级安全。

Agent 可以知道要做什么，但不应该因此知道你的密码。

🤖 AI 相关

1、两个 Harness 设置让 ARC-AGI-3 厂商分数从 13.3% 升到 38.3% 厂商 Benchmark

模型没有升级，编排方式却让分数接近翻三倍。

事实边界：数字来自 OpenAI 在指定公开任务集上的实验，不能外推为模型整体能力提升三倍，也不能直接用于跨模型比较。

🧩 本期概念库

1. 凭证平面（Credential Plane）

一句话解释：把密码、OAuth、Scope、连接身份和 Token 生命周期从模型上下文与 Agent 进程中分离出来的执行层。

为什么重要：Agent 可以组合工具，但不应因此获得可长期复用的底层凭证。

团队应用：使用短期 Runtime Token、最小 Scope、Action 白名单、脱敏日志和可验证撤销。

2. Harness 效应（Harness Effect）

一句话解释：上下文保留、压缩、重试、终止和工具协议会显著改变同一模型的能力、成本与失败形态。

为什么重要：不固定 Harness，就无法公平比较模型或判断优化来自哪里。

团队应用：评测记录模型、提示、工具、Harness 版本、环境和随机性，并保留完整轨迹。

3. 持续通过率（Pass^k）

一句话解释：衡量同一任务连续多次都正确，而不是多次尝试中至少成功一次。

为什么重要：涉及邮件、权限、资金和生产状态时，任何一次失败都可能留下不可逆副作用。

团队应用：同时报告 pass@k、持续通过率和最终状态正确率。

4. 策略执行点（Policy Enforcement Point）

一句话解释：在请求、工具调用或数据写入发生前，由确定性系统执行预算、权限、网络和数据规则。

为什么重要：可观测性只能解释事故，执行点可以在事故发生前阻断。

团队应用：把硬预算、域名白名单、凭证注入、PII 检查和高风险确认放在模型外部。
