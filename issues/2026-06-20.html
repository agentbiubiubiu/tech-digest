第 42 期：Agent 开始走出屏幕，控制面比能力更关键

第 42 期 · 2026年6月20日，星期六

✨ 本期亮点：Claude Opus 4.7 接机器狗做 Project Fetch 平均 12分7秒 · DeepMind 发布 AI Control Roadmap · Cloudflare 把漏洞发现 Agent 做成持久化 harness · Netflix Data Canary 要在 10 分钟内阻断坏数据 · MosaicLeaks 把研究 Agent 查询泄漏从 34.0% 降到 9.9% · OpenAI/GitHub 同步强化 AI credit 用量治理 · Modal DFlash 让 Qwen 3.5 122B-A10B 在 B200 上超过 1000 tok/s

Anthropic Project Fetch Phase Two 把 Agent 能力放进真实机器狗实验里。
🎯 本期核心判断：Agent 的竞争正在从「能不能做」转向「能不能被安全、可计量、可回滚地托付」；一旦它们接触真实设备、企业数据、CI 权限和预算，控制面就不再是配套功能，而是产品本体。

先读 Anthropic Project Fetch：看 Agent 如何从 IDE 走向物理世界。

🔥 主故事

Project Fetch Phase Two：Claude 接上机器狗，快了 20 倍，也暴露了最后一道边界

有个实验很直观：同一只商用机器狗，去年还需要人类团队边查资料边接传感器；今年 Claude Opus 4.7 插上 Claude Code 后，很多步骤自己就做完了。

Anthropic 在 2025 年用 Project Fetch 测试非机器人专家能否借助 Claude 操作一只现成机器狗。2026 年他们重跑实验：研究员只负责把笔记本接到机器狗、输入初始提示、批准命令和进入下一步，其余由 Claude Opus 4.7 完成。

核心冲突软件 Agent 的泛化速度正在逼近物理世界，但真实世界的闭环控制、误差反馈和安全边界还没有被模型能力自动解决。
转折点最关键的转折不是 Claude 会写代码，而是它能快速找到接入机器狗视频、雷达和控制接口的路径；但到了推动沙滩球回到目标点这类精细闭环任务时，它仍然失败。
为什么现在发生模型从 coding agent 获得的工具使用、调试、环境探索能力，正在迁移到传感器、机器人和硬件接口；这让 physical agentic AI 从演示叙事变成工程问题。
对团队的启发凡是要让 Agent 接触真实设备、生产数据、交易权限或 CI/CD 权限，都要先定义沙箱、最小权限、人工确认点、实时监控和失败后的可撤销路径。

📰 科技动态

1、Cloudflare：把漏洞发现 Agent 做成可持久化 harness confirmed

为什么一群 subagents 还不够？因为安全分析需要记住几百条并行假设。Cloudflare 把漏洞发现从一次性提示升级成多阶段 harness，强调状态持久化、去重、可恢复和自动 triage。真正的判断是：企业级安全扫描不是更长的 prompt，而是可审计的工程系统。

2、Netflix Data Canary：坏数据也需要 canary，不只是坏代码 confirmed

没有上线代码，系统还是坏了，因为坏的是数据。Netflix 复盘 catalog metadata feed 被清空导致播放链路出问题的事故，并用 Data Canary 在生产流量下验证数据转换，目标是在 10 分钟内发现并阻断坏数据。

3、GitHub Actions 把 workflow 触发权收进规则集 announced

一个 CI 工作流能不能跑，不应该只由仓库里那份 YAML 决定。GitHub 的 workflow execution protections 让企业/组织用规则集限制 actor 和 event，能把 pull_request_target、workflow_dispatch 等高风险触发源纳入统一策略。对开源仓库和 Agent PR 都是实用的供应链防线。

4、JEP 401 把 Java 价值类推向 JDK 28 预览 announced

Valhalla 最值得关注的不是语法，而是 Java 对象身份这笔长期税。JEP 401 让开发者显式声明没有身份的 value class，使 JVM 能更自由地优化内存占用、局部性和 GC；这会长期影响高吞吐 Java 服务、交易系统和内存密集型代码。

🤖 AI 相关

1、Google DeepMind 发布 AI Control Roadmap announced

如果 Agent 足够有用到必须部署，就不能只靠它「乖」。DeepMind 的路线图把 advanced internal agents 当作潜在 insider threat，用 sandboxing、endpoint security、prompt injection resistance、AI supervisors、coverage/recall/time-to-response 等指标组成 defense-in-depth。它不是模型能力新闻，而是 Agent 平台安全工程新闻。

2、MosaicLeaks：深度研究 Agent 的查询日志会拼出私密事实 confirmed

泄密不一定来自一句危险 query，而可能来自多次正常查询叠起来的马赛克。MosaicLeaks 用 1,001 条多跳研究链评估深度研究 Agent，发现只优化任务成功会加剧泄漏；PA-DR 把答案/完整信息泄漏从 34.0% 降到 9.9%，同时严格链成功率从 48.7% 提到 58.7%。

3、Modal：speculative decoding 正在变成推理系统杠杆 announced

当大家还在为 2% 的 kernel 优化熬夜，Modal 说更大的杠杆是推测解码。它发布 DFlash speculator，称覆盖多款 Qwen 3.5 模型，在多种工作负载上额外带来 5-20% 加速，并让 Qwen 3.5 122B-A10B 在 B200 单节点 concurrency 1 下超过 1000 tok/s。

4、OpenAI 企业 credit analytics：Codex 成本治理进入管理台 announced

企业 AI 不再只是开权限，开始像云账单一样被治理。OpenAI 新增 ChatGPT 与 Codex credit usage analytics，可按用户、产品、模型拆分，并通过统一 Cost API 接入自有系统；同时提供默认、分组和个人覆盖的额度控制。

📝 文章推荐

1、Is it agentic enough? Benchmarking open models on your own tooling

以后软件 API 不只给人用，也要给 Agent 顺手用。Hugging Face 用 transformers 做案例，不只评估最终答案，还评估 Agent 如何发现工具、绕路多少、成本多少。这篇值得读，因为它把「Agent 友好」从感觉变成可跑的 harness。

2、Aikido Code Audit：AI 安全审计开始填补 SAST 与渗透测试之间的空白

Aikido 把 Code Audit 定位在规则型 SAST 和人工渗透测试之间：它读取静态源码，追踪跨文件、多步骤、意图相关的漏洞链。官方称早期测试能覆盖完整 pentest 约 70-80%，成本低约 10x；这些数字需要按厂商自报处理，但方向非常值得关注。

3、AI agents now make up the majority of web traffic

WorkOS 借 Cloudflare Radar 的数据讨论一个产品层变化：自动化请求已经超过人类 HTML 流量，AI Agent 可能一次替用户访问上百个页面。文章真正有用的点不是夸张流量数字，而是提醒产品指标、认证、风控、限流和商业转化都要区分「人」和「代理」。

🧩 本期概念库

1. Physical Agentic AI

一句话解释：Agent 不只操作软件工具，还能接入传感器、机器人、控制器和真实设备。
背景来源：Anthropic Project Fetch Phase Two
为什么重要：它把 AI 风险从信息错误扩展到物理动作错误。
团队应用场景：凡是 Agent 触达真实设备或生产动作，都要先设计人类接管和动作回滚。

2. AI Control

一句话解释：假设模型对齐不完美，仍通过系统级检测、预防、响应和权限控制降低风险。
背景来源：Google DeepMind AI Control Roadmap
为什么重要：这是 Agent 安全从模型研究走向平台工程的语言。
团队应用场景：将 coverage、recall、time-to-response、最小权限和实时阻断加入 Agent 平台验收。

3. Data Canary

一句话解释：把数据变更像代码发布一样先在真实路径中验证，避免坏数据进入主流量。
背景来源：Netflix Data Canary
为什么重要：推荐、风控、交易、内容系统很多事故来自数据而非代码。
团队应用场景：关键数据 feed 要有 schema、语义、空值、体量、业务指标级 canary。

4. Mosaic Leakage

一句话解释：单条外部查询不敏感，但多条查询日志组合后可推断私有事实。
背景来源：MosaicLeaks
为什么重要：它说明隐私泄漏面不只在模型输出，也在 Agent 的工具调用轨迹。
团队应用场景：内部研究 Agent 外部检索前要做 query redaction、私有实体屏蔽和日志访问控制。
