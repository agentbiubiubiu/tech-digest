第 69 期：当文档开始携带指令，AI 工作流就成了新的供应链

第 69 期 · 2026年7月30日，星期四

✨ 本期亮点：Word 提示注入被报告可随新文档继续传播，公开时变体仍可复现 · Socket 报告 18 个 npm 包把恶意加载链拆进多个依赖 · HANDBOOK.md 作者基准中，124 页规则下最佳严格通过率仅 36.2% · Airbnb 用 Eval-Driven Development 把真实失败模式写成持续评测 · Datadog 报告用 9700 万参数模型把每日约 100 亿事件筛到约 1 万条再交给 Agent · X 社区雷达成功抓取 PaperPush、Claude 移动教程与 Stanford LLM 课程线索

研究者演示：外部 Word 文档中的隐藏提示可影响 Copilot 输出，并随生成的新文档继续传播。该结论来自协调披露研究，微软未发布独立公告。

🎯 本期核心判断：当 AI 开始读取、改写并转发工作内容，文档、规则和上下文本身都会成为可执行供应链。团队不能只给模型更多提示词，而要把来源隔离、确定性校验、最小权限和可追踪评测放到模型之外。

🔥 主故事

一份 Word 文档，如何把提示注入带进下一份报告

攻击者不需要让员工运行宏，只要让 Copilot 把一段隐藏指令当成工作上下文。

安全研究者 Håkon Måløy 报告，他在外部 Word 文档中放入白底白字的隐藏提示。当用户让 Copilot 参考这份文档处理财务数据时，模型会按攻击者意图修改结果，并把隐藏提示复制进新生成的内部文档。以后即使原始恶意文件不再出现，只要同事继续引用被污染的文档，攻击链就可能延续。

核心冲突Agent 必须读取业务文档才能创造价值，但模型看到的“资料”和“指令”往往进入同一上下文。传统文件边界仍然存在，语义边界却被压平：一个被授权读取的文档，也可能借模型获得写入和传播能力。
转折点关键变化不是“又一个提示注入”，而是传播机制。攻击指令不再只影响当前对话，而会被写进新的业务产物，在后续检索和生成中再次触发。文档由静态数据变成携带行为的节点。
为什么是现在企业正在把 Copilot、Coding Agent 和知识库接入同一条工作流。读、写、搜索、转发一旦连通，单次提示注入就可能升级为跨文档、跨会话、跨人员的供应链问题。
对团队的启发给企业 Agent 增加四道闸门：外部内容与用户指令分通道；生成物记录输入来源；金额、权限、身份和配置变更使用非模型校验；跨文档复制隐藏内容、异常格式或不可见文本时触发阻断与审计。

协调披露历时 144 天研究者称 2026 年 3 月 31 日微软确认所报告行为研究者记录两轮缓解措施研究者称 7 月 28 日仍可用变体复现

我的判断：这不是微软已经确认的通用“AI 蠕虫”事件，而是研究者在协调披露后公开的可复现实验；微软没有独立发布公告或 CVE。工程上仍应按真实攻击类别处理：模型输入必须保留来源标签，外部内容不能获得指令优先级，写入的新文档要记录生成链，敏感数据变更要经过确定性校验。

当文档既是资料又能携带指令，文件流转就变成了代码执行链。

📰 科技动态

1、Socket 报告：18 个 npm 包把 RAT 加载链拆进多个依赖 安全厂商报告

单个包看起来无害，整棵依赖树拼起来才出现完整攻击链。

Socket 分析称，攻击者把恶意逻辑拆到多个看似正常的 npm 包中，组合后可绕过 Node.js vm 沙箱、下载跨平台 RAT，并包含 Aone、钉钉和中文开发工具相关逻辑。

为什么重要：Web、Node.js 和跨端团队应审计依赖图、安装脚本与运行时下载行为，而不是只看单包代码和下载量。

事实边界：包链和行为来自 Socket 研究；“针对阿里开发者”是根据仿冒包名及 Aone、钉钉相关代码作出的归因，不是阿里官方确认。

2、微软确认 Anthropic 投资带来 32 亿美元会计收益 已证实

云平台既投资外部模型公司，也在用自研模型降低推理成本。

微软 FY2026 Q4 电话会披露，Anthropic 投资本季度带来 32 亿美元收益；同期季度资本开支为 410 亿美元，并继续强调自研 MAI 模型与可替换模型架构。

为什么重要：企业应把模型视为可替换组件，把长期资产放在数据、评测、业务上下文和治理层。

事实边界：32 亿美元是微软官方披露的投资会计收益，不等同于现金回款、融资额、收购价格或 Anthropic 当前估值。

3、FCC 将外国制造的机器人和电力逆变器加入 Covered List 已证实

机器人还未大规模进入家庭，监管已经把摄像头、执行器和远程更新视为基础设施风险。

FCC 宣布把外国生产的机器人与电力逆变器加入限制清单，新设备原则上无法获得进入美国市场所需的设备授权；政府认定无国家安全风险时可例外，已安装设备不受影响。

为什么重要：机器人、IoT 和客户端团队要提前盘点组件来源、远程控制面和设备认证，不要等发布前再补合规。

事实边界：限制由 FCC 官方公告确认；它针对新设备授权和进口准入，不是召回或禁用现有设备，并保留例外机制。

4、Cloudflare 为源站 mTLS 加入后量子身份认证 官方发布

后量子迁移不只要保护密文，还要避免未来有人伪造服务器身份。

Cloudflare 为 Authenticated Origin Pulls 与 Custom Origin Trust Store 加入基于 ML-DSA 的后量子认证，覆盖 Cloudflare 到源站的身份校验链路。

为什么重要：涉及 CDN、API 网关、源站 mTLS 和长期敏感数据的后台团队，应开始盘点签名算法与证书链。

事实边界：功能范围由 Cloudflare 官方确认；当前只覆盖指定源站认证产品，不代表所有客户端到站点连接都已完整后量子化。

5、GitHub 建议把普通 Dependabot 更新降频，安全更新保持快速 官方工程实践

安全机器人也会制造足够多的噪声，让真正紧急的更新被忽略。

GitHub 以 Microsoft GCToolkit 为例，建议按生态合并普通版本更新并降低到月度节奏，同时保持安全更新快速处理，以减少重复 PR、CI 和人工审查。

为什么重要：Web、iOS、Android、PC 和后台仓库都可直接调整 `dependabot.yml`，把维护更新与安全响应拆成不同节奏。

事实边界：92/578 提交与 61 次升级来自 GitHub 对单一案例仓库的统计，不能外推为所有仓库的普遍收益。

🤖 AI 相关

1、HANDBOOK.md：长达 124 页的规则，最佳严格通过率仍只有 36.2% 作者 Benchmark 报告

把规则完整塞进上下文，不等于 Agent 在第 30 步仍然服从。

论文用 65 个跨金融、医疗账单、保险、物流和 HR 的任务，测试 Agent 能否持续遵守 20 至 124 页规则。在必须满足全部条件的严格评分下，作者报告 30 种配置中最佳通过率为 36.2%。

为什么重要：关键政策要转为确定性校验、权限限制和可测试验收条件，不能只依赖系统提示。

事实边界：数字来自作者公开基准，尚未看到独立复现；任务和规则为研究环境，不能直接外推到所有企业流程。

2、Airbnb 用 Eval-Driven Development 把 GenAI 失败模式写进开发流程 官方工程实践

AI 功能的规格，往往是在真实失败输出里被发现的。

Airbnb 工程团队把 EDD 类比 TDD：先检查真实输出，提炼失败模式，再把它们编码为确定性检查、LLM Judge 与人工评审，并增加 Agent trace 评测。

为什么重要：适合 Web、移动端和后台 AI 功能：先建立失败样本，再选择规则、Judge 或人工评审，不要只盯一个总分。

事实边界：样本规模和 Judge 一致率是文章中的实践建议或示例，不是 Airbnb 全部生产系统的统一指标。

3、Datadog 报告：先把每日约 100 亿事件筛到约 1 万条，再交给 Agent 厂商工程报告

昂贵推理的前提，不是更大的模型，而是更好的候选集。

Datadog 介绍安全检测管线：约 9700 万参数的 Mambark 模型先高召回筛选事件，把每天约 100 亿条输入缩到约 1 万条，再由更昂贵的 Agent 做解释和调查。

为什么重要：后台与安全团队可复用两级架构：便宜模型做高召回筛选，Agent 只处理带证据的少量候选。

事实边界：规模、模型效果和成本估计来自 Datadog，未披露完整硬件与独立复现；当前面向设计伙伴，不能视为通用生产 Benchmark。

4、BAIR 用 K-Search 自动搜索 CUDA 到 MLX 的高性能实现 作者 Benchmark 报告

Agent 的优势不是一次写对 kernel，而是把编译、测量和改写变成搜索循环。

Berkeley 团队让 Agent 迭代生成、编译和测量 MLX kernel。作者报告注意力实现从 CUDA 基线的 0.26 倍提升到 0.97 倍，并在特定 Mamba prefill 场景达到相对 mlx-lm 最高 20 倍。

为什么重要：端侧 AI 与客户端性能团队可借鉴：固定正确性门槛和真实硬件 Benchmark，让 Agent 优化可测目标。

事实边界：结果来自作者在指定模型、硬件与 kernel 上的测量；20 倍不是所有 MLX 模型或任务的普遍提升。

5、美团发布 CatPaw，称内部覆盖 9 万员工与 3 万个 Agent 产品已发布；规模为厂商自报

当 Agent 数量达到员工人数三分之一，权限、凭证和成本才是主系统。

美团发布基于 LongCat 2.0 的 CatPaw，覆盖个人工作台与企业 Managed Agents，提供云端运行、多 Agent 并发、凭证托管、租户隔离、可观测性和私有化部署。

为什么重要：企业 Agent 平台要补齐沙箱、凭证代理、租户隔离、观测、成本和跨端任务连续性。

事实边界：产品与体验入口由美团官方确认；9 万员工、3 万 Agent、冷启动等规模数据为美团自报，未独立验证。

🧩 本期概念库

1. 上下文供应链（Context Supply Chain）

一句话解释：进入模型上下文的文档、网页、检索结果和工具输出，会共同影响后续决策与生成物。

为什么重要：任一外部内容都可能携带误导指令，并通过新生成内容继续传播。

团队应用：为每段上下文保留来源、信任级别、权限和传播记录。

2. 语义信任边界（Semantic Trust Boundary）

一句话解释：传统权限只判断能否读取文件；语义边界还要判断文件中的文字能否被当作指令执行。

为什么重要：“可读”不应自动等于“可改变 Agent 行为”。

团队应用：把用户指令、系统规则、外部资料和工具结果分通道处理。

3. 严格通过率（Strict Pass Rate）

一句话解释：任务必须满足全部规则才算通过，而不是部分正确或模型自称已完成。

为什么重要：长流程中一个关键条件失败，就可能让整体结果不可用或不合规。

团队应用：对资金、权限和合规流程使用全条件验收，并报告失败条件。

4. 分层推理（Cascaded Reasoning）

一句话解释：先用便宜、快速的规则或小模型筛选，再把少量高价值候选交给昂贵 Agent 深入处理。

为什么重要：它把 Agent 成本集中在真正需要解释和决策的输入上。

团队应用：记录每一层的召回、误报、延迟和单位有效结果成本。

用一个上午把未来住宅搬进 Vision Pro

一个长期闲置的头显，在最难撤销的现实决策上找到了用途：墙到底应该放在哪里。
