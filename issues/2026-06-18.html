第 41 期：AI 开始走进实验室，真正的护城河变成反馈闭环

第 41 期 · 2026年6月18日，星期四

✨ 本期亮点：OpenAI + Molecule.one AI 化学家跑 10,080 次反应 · LifeSciBench 用 750 个专家任务重写生命科学评测 · Vercel Connect/eve 补 Agent 短期凭证、沙箱和审批 · GLM-5.2 以 1M context 追长程 coding · MolmoMotion 开放 3D motion forecasting 数据与模型 · HF ARD 把工具发现层标准化 · Tailscale 日志流支持 Azure Blob Storage

OpenAI 与 Molecule.one 的 AI 化学家把 GPT-5.4 接入 Maria Lab，让假设接受真实实验和 bench-scale 复验。
🎯 本期核心判断：AI 的下一阶段不是更会聊天，而是能不能在真实工具、真实实验、真实权限和真实证据里闭环迭代；模型能力会变成组件，反馈闭环和控制面会变成护城河。

🔥 主故事

AI 化学家跑了 10,080 次反应：答案不在模型里，而在实验台上

如果一个模型真的想帮科学家，它不能只写一段漂亮解释，还得提出假设、安排实验、读回数据，然后承认哪里还没被证明。

OpenAI 与 Molecule.one 把 GPT-5.4 接入 Maria，一个与高通量实验室集成的 agentic chemistry AI。任务不是回答化学题，而是在几个重要反应类别中寻找可改进方向。三个月里，系统生成研究提案、设计实验、分析数据，再提出后续实验；人类化学家负责 steering、选择要测试的提案、修正少量实验计划，并做 bench-scale 复验。

核心冲突AI for Science 的核心冲突不是模型会不会推理，而是推理能不能被现实世界的仪器、噪声、材料成本和专家复核校正。没有实验闭环，模型只是猜；接上实验闭环，模型才开始像研究伙伴。
转折点最有意思的不是 GPT-5.4 找到了 TEMPO，而是它在第一轮数据后继续缩小问题，提出更聚焦的第二轮实验，并发现更便宜的 4-hydroxy-TEMPO 也能维持接近效果。
为什么现在发生过去一年 AI 的主线一直是 Agent 会不会写代码、会不会调用工具。今天这条新闻把问题推到更硬的地方：如果工具是高通量实验室、输出是化学产率、失败会消耗真实材料，Agent 系统就必须接受可测量的现实反馈。
对团队的启发团队做 Agent 时也应按这个模式思考：先定义可测量目标，再设计可执行工具，再把结果回写成下一轮决策；没有证据回路的自动化，只是在更快地产生无法验证的输出。

10,080 次 Maria Lab 反应88% boronic acids yield 改善83% sulfonamides yield 改善平均 yield 16.6% → 25.2%>30% yield 占比 15.6% → 37.5%11/14 bench-scale substrate pairs 复验提升

我的判断：我的判断是，AI 科学突破的真正门槛不是“模型懂不懂科学”，而是“组织能否把模型、自动化设备、数据回流、专家审查和风险边界接成一个可重复的实验系统”。未来高价值 AI 产品更像一套闭环基础设施，而不是一个孤立模型。

AI 真正进入科学，不是因为它说得更像专家，而是因为它开始接受实验台的反驳。

来源：openai.com

📰 科技动态

1、Vercel eve：Agent 框架开始把 durable execution、沙箱、审批和 eval 作为默认配置 confirmed

钩子：当每个团队都在手搓同一套 Agent plumbing，框架就出现了。Vercel 发布开源 agent framework eve，内置 durable execution、sandboxed compute、human-in-the-loop approvals、subagents 和 evals，并称这是其内部 agents 的运行底座。对团队的启发是，生产级 Agent 的最小集合已经从 prompt 扩展到执行、隔离、审批、trace 和测试。

2、Vercel Connect：让 Agent 临时借权限，而不是永久拿钥匙 confirmed

钩子：长期 token 放进环境变量，是 Agent 时代最容易被忽视的爆炸半径。Vercel Connect 进入 Public Beta，用 runtime credential exchange 替代长期 provider token：应用证明身份后拿到 scoped、short-lived credential，并支持 Slack、GitHub、Linear 等连接器。它的意义不是又一个集成，而是把 Agent 权限生命周期变成平台能力。

3、Tailscale 支持把日志流到 Azure Blob：最无聊的功能，往往最接近安全基本功 confirmed

钩子：安全团队很多时候缺的不是新告警，而是日志能不能进同一个地方。Tailscale 新增 Azure Blob Storage 作为 log streaming destination，让 configuration audit logs 和 network flow logs 进入存储、合规、检测和调查链路；加上 AWS S3、Google Cloud 后，三大对象存储都覆盖。

4、Vercel Passport Public Beta：预览环境也要服从企业身份边界 confirmed

钩子：Preview deployment 不能只靠“链接别外传”来保护。Vercel Passport 进入 Public Beta，允许企业用自有 OIDC 身份提供商保护 deployments，并向请求注入签名 identity token。对前端平台团队来说，这意味着预览环境、安全审计和客户协作的边界会更像正式环境。

5、Systems Approach：云正在反过来改造网络控制面 opinion

钩子：云不是只运行在网络之上，它也在把网络运维变成更像云平台的控制面。Systems Approach 从 Internet 与 Cloud 的相互塑造讲到 YANG、NETCONF、OpenConfig 和 gNMI，解释为什么网络团队正在采用更自动化、更可观测、更 API 化的运维语言。对 SRE 来说，应用可靠性之外，网络控制面也在重构。

🤖 AI 相关

1、LifeSciBench：生命科学评测从“会不会答题”走向“能不能像研究合作者” confirmed

钩子：真正的科研任务很少是干净的单选题。OpenAI 发布 LifeSciBench，包含 750 个专家撰写任务、1,062 个 artifacts、19,020 条 rubric criteria 和 453 位专家 reviewer，覆盖证据处理、实验设计、验证运营、转化风险等真实工作流。它的价值是把 AI 评测从“知道多少”推向“是否能在不完整证据下给出可用判断”。

2、OpenAI Deployment Simulation：模型发布前，先在影子真实世界里跑一遍 confirmed

钩子：红队像靶场，真实用户像城市；两者之间缺一个影子城市。OpenAI 提出 deployment simulation，用隐私保护方式回放历史真实对话，在候选模型上线前预测行为分布，并称已用于多个 GPT-5-series Thinking deployments 和带工具的 agentic rollout。它说明前沿模型发布正在从题库评测走向准生产仿真。

3、GLM-5.2：开放模型把 1M context 做成长程工程系统 confirmed

钩子：1M context 很容易宣称，难的是在混乱的长程 coding trajectory 里保持可靠。Z.ai 发布 GLM-5.2，强调 solid 1M-token context、IndexShare、MTP speculative decoding、agentic RL 和 anti-hacking 训练；Hugging Face 文中称它在多个长程 coding benchmarks 中成为最高排名开源模型。开放权重阵营的竞争正在从参数量转向系统稳定性。

4、MolmoMotion：世界模型开始预测 3D 运动，而不是只回看视频 confirmed

钩子：机器人拿杯子之前，先得想象杯子会怎么动。Ai2 发布 MolmoMotion，用语言指令、视觉输入和 3D query points 预测未来轨迹，并开放 MolmoMotion-1M 与 PointMotionBench。1.16M videos、2.7K human-validated benchmark clips 让“物理运动预测”有了可评测底座。

5、Agentic Resource Discovery：MCP 之后，Agent 还需要“发现层” confirmed

钩子：工具调用解决了“怎么用”，但没有解决“该找谁”。Hugging Face 介绍 Agentic Resource Discovery draft specification，由 Microsoft、Google、GoDaddy、Hugging Face 等参与，目标是在 MCP、Skills、A2A 前面加一层 federated registry，让 agent 运行时搜索工具、技能和其他 agent，而不是预装所有能力。

6、Strands + LeRobot：Agent 开始把仿真、策略和真实机械臂串成 loop confirmed

钩子：当 Agent 不只点网页，而是能控制真实硬件，安全边界就从软件事故变成物理事故。AWS 在 Hugging Face 上展示 Strands Agents 与 LeRobot 集成，把 Hub dataset、仿真、policy inference、真实 SO-101 硬件部署和多机器人 mesh 串成一个 agent loop。它很工程化，也足够提醒我们：Physical AI 会放大权限、认证和人工审批问题。

🧩 本期概念库

1. 实验闭环 Agent

一句话解释：Agent 不只输出建议，而是提出假设、调用真实工具或实验系统、读取结果，再进入下一轮决策。
背景来源：OpenAI AI chemist + Latent Space Self-Driving Lab
为什么重要：它把 AI 价值从“像专家一样说话”推到“能被现实反馈纠正”。
团队应用场景：内部 Agent 项目应尽量设计可测量回路，例如自动测试、真实日志、用户行为、审批结果，而不是只收集文本反馈。

2. Runtime Credential Exchange

一句话解释：应用或 Agent 在运行时用自身身份换取 scoped、short-lived credential，而不是持有长期 provider token。
背景来源：Vercel Connect
为什么重要：这是 Agent 接入真实业务系统后的第一道权限工程。
团队应用场景：禁止把高权限长期 token 直接交给 Agent；把权限请求、作用域、有效期和审计日志纳入平台层。

3. Agentic Resource Discovery

一句话解释：位于 MCP、Skills、A2A 之前的发现层，让 Agent 运行时搜索工具、技能和其他 Agent。
背景来源：Hugging Face ARD
为什么重要：当工具数量从十几个变成几千个，硬编码工具列表不可持续。
团队应用场景：搭建内部工具目录时，提前定义 metadata、权限、质量评分和信任等级，不要只堆 MCP endpoint。

4. Motion Forecasting Interface

一句话解释：用语言和视觉输入预测未来 3D 轨迹，作为机器人规划与视频生成之间的中间表示。
背景来源：MolmoMotion
为什么重要：物理智能需要可传递、可评测、比像素更稳定的运动表示。
团队应用场景：做机器人或自动化系统时，把“预测状态变化”作为独立接口，而不是直接端到端生成动作。

5. Benchmark Loop over Prompt Trick

一句话解释：让 Agent 在生成、运行、测量、修复的循环里优化，而不是靠一次提示词猜对。
背景来源：Intel XPU Kernel Skill + OpenAI Deployment Simulation
为什么重要：越接近底层系统和高风险发布，越需要用可重复评测替代主观感觉。
团队应用场景：为代码 Agent、性能优化和发布前验证建立可自动运行的 benchmark loop，并把失败样例纳入回归集。
