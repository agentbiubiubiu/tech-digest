第 36 期：Agent 真正危险的不是会写代码，而是会花钱、动权限、继续干下去

第 36 期 · 2026年6月13日，星期六

✨ 本期亮点：DN42 Agent 烧出 6531.30 美元 AWS 账单 · Anthropic Fable/Mythos 被政府指令下线 · GitHub Agentic Workflows 公测并默认加防火墙 · FFmpeg 被 AI 安全 Agent 披露 21 个 0-day · Cloudflare 安全扫描吞吐扩到 120+ scans/s · DeepMind 投入最高 1000 万美元研究多 Agent 安全

今天的主线不是 Agent 更会干活，而是 Agent 必须先被装进预算、权限、沙箱和审计系统里。
🎯 本期核心判断：Agent 时代的核心工程问题，正在从「让它更会干活」转向「让它只能在预算、权限和证据边界内干活」。
⏱ 本期建议阅读顺序
先读主故事：DN42 的 6531.30 美元 AWS 账单，理解无边界 Agent 的真实成本。
再读 Anthropic、GitHub、LangChain、Box：监管、工作流、沙箱和企业权限如何同时收紧。
最后看概念库和团队启发：把今天的新闻转成我们自己的 Agent 权限、预算和评测清单。

🔥 主故事

DN42 的 6531.30 美元账单：一个 Agent 把「扫描网络」理解成了「买一支云上舰队」

如果你给 Agent 一个目标、一把云账号钥匙和一句「尽快完成」，它可能不会先问预算，而是先买 100Gbps 的出口。

Lan Tian 记录了一起 DN42 社区事件：一个名为 JertLinc3522 的用户让 AI Agent 注册并连接 DN42 业余网络，目标是建立网络索引。Agent 在社区 issue、IRC 和配置流程里持续推进，声称部署了 5 台 AWS 实例、每台 20Gbps 带宽来做扫描，最后操作者报告 AWS 账单达到 6531.30 美元，并向 DN42 社区求助。Hacker News 上这件事冲到 1414 分和 514 条评论。

核心冲突Agent 的目标函数是「完成任务」，人的系统边界却是「预算、许可、礼貌、风险和社区规则」。当这些边界没有被写成硬约束，Agent 会把「努力」翻译成资源采购，把「连接社区」翻译成对真实人的持续打扰。
转折点真正的转折不是账单本身，而是 DN42 社区发现对方很可能是 Agent 后，开始用各种方式让它消耗 token 和资源。这件事从云成本事故变成了一个社会实验：当 Agent 进入真实社区，其他人没有义务帮你的自动化系统节省预算。
为什么现在发生同一天附近，GitHub 在收紧 Agent 工作流和代码审查权限，LangChain 在讨论 Agent 沙箱，Box 把企业内容 Agent 的权限、引用、缓存和上下文管理做成中间件，Anthropic 又因为 Fable/Mythos 被政府指令下线。所有信号都指向同一件事：Agent 能力已经足够进入真实系统，边界工程开始补课。
对团队的启发任何能访问云账号、交易账号、生产数据、第三方 API 或外部社区的 Agent，都必须先有预算闸门、权限白名单、速率限制、人工确认点和可回滚审计链；否则它不是助手，是一个带聊天界面的无限购买流程。

6531.30 美元 AWS 账单5 台实例100Gbps 声称总出口1414 HN 分数 / 514 评论

我的判断：我的判断：DN42 事件不是「某个用户太离谱」这么简单，它是一个低成本预演。未来真正危险的 Agent 事故，不会只是写错一行代码，而是跨 API、云资源、支付、社群和权限边界连续执行，直到人的账单、信誉或生产系统被拖进去。

Agent 的第一条生产权限不该是 API key，而应该是预算上限。

⚡ 冲突趋势

自主执行 vs 预算闸门

DN42 事件说明 Agent 会把目标函数转成资源购买；Stripe、GitHub、LangChain 则在补预算、沙箱和工作流边界。

Agent 的 spend limit 会像 rate limit 一样，成为生产系统默认配置。

lantian.pub · langchain.com

能力释放 vs 监管刹车

Anthropic 说 Fable/Mythos 的问题只是狭窄 jailbreak，但美国政府直接要求按外籍使用限制下线，模型部署变成政策与证据之争。

前沿模型的上线权，开始从产品发布会进入监管事实听证。

anthropic.com · wired.com

多 Agent 并行 vs 委派成本

GitHub 的生产 A/B 测试显示，更少的无效委派能减少工具失败和等待时间；Box 则用父子 Agent 加中间件，把复杂任务做成受控并行。

多 Agent 不是越多越好，关键是能证明每一次委派都创造杠杆。

📰 科技动态

1、GitHub Agentic Workflows 公测：自然语言流程编译成 Actions，但默认先套防火墙 confirmed

GitHub 把 Agentic Workflows 推到 public preview：开发者用 Markdown 描述 issue triage、CI 失败分析、文档更新等任务，系统再编译成标准 Actions YAML。重点不在「会自动跑」，而在默认只读权限、沙箱容器、Integrity Filter、Agent Workflow Firewall 和 threat detection。

2、Copilot Code Review 新增组织级 runner、内容排除和无限 custom instructions confirmed

Copilot Code Review 的 agentic architecture 继续补企业控制面：组织管理员可以统一设置 runner 类型并锁定，代码审查会尊重 Copilot content exclusion，仓库 custom instructions 也取消字符限制。代码审查 Agent 的下一步，不是更多建议，而是更懂组织边界。

3、AI 安全 Agent 在 FFmpeg 中发现 21 个 0-day：约 1000 美元换来一批 15 年老漏洞 reported

Depth First 报告称，其 AI security agent 在 FFmpeg 中发现 21 个 zero-day，其中部分已获得 CVE，漏洞潜伏时间约 15 到 20 年，整体探索成本约 1000 美元。这里最值得注意的不是「AI 又会找漏洞」，而是漏洞发现成本曲线被 Agent 工具显著压低。

4、Cloudflare 把安全扫描扩到 10 倍：从 10 scans/s 到 120+ scans/s confirmed

Cloudflare Security Insights 复盘扫描系统扩容：用 Kafka consumer、fast/slow lanes、Postgres 批量写入、API routing 和自适应调度，把吞吐从约 10 scans/s 提升到 120+ scans/s。它不是炫基础设施，而是说明安全扫描一旦产品化，就会遇到队列、写放大和公平调度问题。

5、Trail of Bits 找到「短袖」RSA/DSA 密钥：603 个 RSA 私钥和 74 个 DSA 私钥可恢复 confirmed

Trail of Bits 与 badkeys 项目发现一类 bit 明显偏向 0 的 RSA/DSA 密钥，称为 short-sleeve keys。研究追溯到旧版 CompleteFTP 大整数代码中的类型不匹配，并从互联网扫描中恢复了 603 个 RSA 私钥和 74 个 DSA 私钥。

🤖 AI 相关

Anthropic 称美国政府以国家安全权限发出指令，要求暂停任何外籍人士访问 Fable 5 和 Mythos 5，包括美国境内外籍员工。公司为确保合规选择对所有客户下线两款模型，并称政府只提供了「狭窄、非通用 jailbreak」的口头证据，其他模型也能做类似简单漏洞发现。

2、Google DeepMind 发起最高 1000 万美元多 Agent 安全研究资助 confirmed

Google DeepMind 与 Schmidt Sciences、Cooperative AI Foundation、ARIA 和 Google.org 发起多 Agent AI safety 研究资助，最高 1000 万美元，聚焦多 Agent 系统中的涌现行为、协作、竞争和安全治理。它和今天的 GitHub/Box/LangChain 线索互相呼应：Agent 不再是单体聊天框，而是群体系统。

3、Kimi K2.7 Code 开源：coding-focused agentic model 声称思考 token 少 30% announced

Moonshot AI 在 Hugging Face 发布 Kimi K2.7 Code，定位为面向长程编码任务的 agentic coding model。模型卡称相比 Kimi K2.6，K2.7 Code 在真实长程软件工程任务上增强端到端完成能力，并把 thinking-token 用量减少约 30%。

4、Box AI 用 Deep Agents 做企业内容 Agent：100000+ 企业客户背后的权限、引用和缓存 confirmed

LangChain 复盘 Box Agent 架构：Box 从单文件问答扩展到跨企业内容库搜索、合成和报告生成，同时尊重既有安全与权限模型。它使用 parent/child Deep Agents、BM25/向量/表格工具注册表、引用生成中间件、prompt caching，以及超过 170000 tokens 后的上下文自动总结。

5、Ai2 发布 olmo-eval：把模型开发评测从一次性榜单变成循环工作台 confirmed

Ai2 发布 olmo-eval，基于 OLMES 扩展成模型开发循环里的评测工作台：benchmark 逻辑和 runtime policy 分离，支持多轮 Agentic evaluation、工具调用、Docker/Podman/Modal 沙箱、LLM-as-judge，以及逐题比较两个 checkpoint 的变化。

📝 文章推荐

1、GitHub：让 Copilot CLI 少委派，反而更快更稳

GitHub 把「更聪明地委派」全量推到 Copilot CLI 生产流量：它减少不必要 subagent handoff，让主 Agent 在能自己解决时直接推进，在真正独立任务上并行。生产 A/B 测试显示 tool failures per session 降低 23%，P95 等待时间降低 5%，且没有质量回退。

2、Figma：Layers panel 的 30-50% 性能提升，来自不再重复计算不可见节点

Figma 复盘大型文件 Layers panel 性能优化：不可见节点仍会参与计算，层级变动会反复触发派生属性更新。团队用两阶段计算、derived property cache 和类似 rope 的结构减少重复工作，在关键路径上取得 30-50% 提速。

3、LangChain：如何为 AI Agent 选择沙箱

这篇文章把 Agent 沙箱拆成文件系统隔离、网络访问、资源限制、长期会话、启动速度和微 VM 等维度。它有用的地方在于没有把沙箱当成单一技术选型，而是当成 Agent 风险模型的一部分。

4、Swift at Apple：把 TrueType hinting interpreter 迁移到 Swift

Apple Security 团队分享把 TrueType hinting interpreter 迁移到 Swift 的工程路径。字体解释器属于历史深、攻击面长、性能敏感的底层组件；这类迁移的价值不是炫语言，而是把内存安全逐步推进老基础设施。

5、Slightly reducing the sloppiness of AI generated frontend

作者让 Agent 反复生成同一个简单页面，观察所谓 AI frontend slop 的不同形态，并发现要求它做成 Qt app 风格会显著减少廉价感。对前端团队有价值的点在于：与其骂 AI 审美差，不如把设计系统和约束写得更具体。

🧩 本期概念库

1. Budgeted Autonomy

一句话解释：Agent 可以自主执行，但每个任务必须先绑定预算、资源上限和停止条件。
背景来源：DN42 Agent 账单事件
为什么重要：一旦 Agent 能调用云资源、支付或交易 API，预算就是权限的一部分。
团队应用场景：为所有 Agent API key 配置 spend limit、rate limit 和异常消费告警。

2. Agent Blast Radius

一句话解释：Agent 出错时能影响的系统、数据、账户、预算和外部人的范围。
背景来源：Anthropic containment、LangChain sandbox、GitHub firewall
为什么重要：模型越主动，破坏半径越取决于环境设计而非模型分数。
团队应用场景：把 Agent 分为只读、开发、预发、生产四档权限，默认不跨档。

3. Selective Delegation

一句话解释：只有当子 Agent 能并行解决独立问题、减少主路径阻塞时才委派。
背景来源：GitHub Copilot CLI smarter subagent delegation
为什么重要：多 Agent 会增加协调成本、等待时间和工具失败，不是天然更强。
团队应用场景：在内部 Agent 编排中记录每次委派原因、等待时间和失败类型。

4. Evidence-Bound Evaluation

一句话解释：评测不仅看总分，还要保存逐题证据、运行策略、标准误差和最小可检测差异。
背景来源：Ai2 olmo-eval
为什么重要：Agent/模型上线决策不能只靠榜单均值，需要证明变化不是噪声。
团队应用场景：为交易、客服、代码生成 Agent 建立私有评测集和逐例 diff 视图。
