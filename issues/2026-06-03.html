🧩 本期概念库

1. Inference Theft（推理盗用）

一句话解释：攻击者将他人付费 AI 推理包装成兼容 API 转卖；防御关键是 per-request 人机校验，会话级限流会被摊薄失效。
背景来源：Vercel 博客 token-theft 事件
为什么重要：AI 端点安全模型必须从「登录验证」升级为「每次请求验证」。
团队应用场景：所有暴露 AI 端点的服务，需在请求级别做 BotID 或 challenge，不能仅依赖登录态。

2. Triple Debt Model（三重债务模型）

一句话解释：技术债在代码，认知债在团队共享理解，意图债在外部化目标与约束。AI 加速写码却可能加剧后两者。
背景来源：ACM Queue: Margaret-Anne Storey 论文
为什么重要：AI 团队管理需要同时关注代码质量、团队理解力和目标对齐三个维度。
团队应用场景：在 AI 大量生成代码时，需要额外投资于文档、设计意图记录和知识共享机制。

3. Dual Exponentials（双轨指数）

一句话解释：闭源以集成产品与顶级智能 monetize 高端知识工作；开源以可组合栈、commodity 定价渗透长尾企业与垂直 agent。两者不是零和，但经济指数不同。
背景来源：Nathan Lambert (Interconnects)
为什么重要：理解 AI 市场结构，做正确的技术选型与投资判断。
团队应用场景：评估「用 frontier 闭源模型 vs 开源 self-host」时，需按场景分层而非全选一种。

4. Token-In Token-Out (TITO)

一句话解释：工具返回必须作为已采样 token 序列的字面追加，保证 RL 梯度与推理时 token 边界一致。否则多轮 Agent RL 训练会因 BPE 漂移失败。
背景来源：Hugging Face Blog: Agentic RL
为什么重要：正在做 Agent RL 训练的团队，很可能踩了这个看不见的坑。
团队应用场景：检查 Agent 训练管线中 tool message 是否被重新 tokenize，确保 prefix-preserving。

5. Recall-gated Precision（召回门控精度）

一句话解释：漏掉任一真实根因则该次得分为 0；找全后按提交实体精度计分。用于评估 SRE Agent 的运维能力。
背景来源：IBM ITBench-AA + Artificial Analysis
为什么重要：Agent 评测不能只看「答对了几个」，漏检致命问题的惩罚必须远大于误报。
团队应用场景：在设计 Agent 运维评测时，采用 recall-gate 机制防止 Agent 跳过难题只回答简单问题。
