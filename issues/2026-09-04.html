第 90 期：烧掉 200 亿 Token 以后，Astra 仍不能按“每小时 6 美元”估价

第 90 期 · 2026年9月4日，星期五

✨ 本期亮点：OpenAI 宣布 GPT-6 Astra 先向少量组织开放，随后计划覆盖 ChatGPT 付费套餐、API 与 AWS；企业工作区首发默认关闭 · Astra API 标准价格为每百万输入 10 美元、输出 50 美元，缓存读写另计；Fast 模式最高 2 倍速度、价格也是标准模式的 2 倍 · Latent Space 团队称测试消耗超过 200 亿 Token；其“每小时低于 6 美元”主要由输出速率乘输出单价得到，不等同于完整任务账单 · X 上的飞行模拟器演示记录 Astra 约 28.55 美元、GPT-5.6 Sol 约 6.61 美元，但前者用了 6 个子 Agent 与 ultra、后者单 Agent 与 high，不能作为同配置 Benchmark · npm 可信发布现在支持同一包的多套 OIDC 配置，并建议默认先进入人工批准的 staged publishing · 本次检查 105 个正式源，34 个命中条件缓存；35 条窗口内记录压缩为 28 张候选卡，证据深抓严格限制为 20+4

配图来自 Latent Space；200 亿 Token 与每小时 6 美元均为测试团队口径，不是独立 Benchmark。

🔥 主故事

“每小时 6 美元”听起来像人力报价，但 Agent 账单按任务发生

33 个输出 Token 每秒，乘上一小时，再乘每百万输出 50 美元，结果约为 5.94 美元。公式没有错，错的是把这个结果叫成完整工作成本。

2026 年 9 月 3 日，OpenAI 发布 GPT-6 Astra，先向少量组织开放，并计划随后扩展到 ChatGPT 付费套餐、API 与 AWS。官方标准 API 定价为每百万输入 10 美元、输出 50 美元，缓存读写另计。Latent Space 称早期测试消耗超过 200 亿 Token，并以约 33 个输出 Token 每秒推导出“低于 6 美元一小时”。

核心冲突这个时薪只覆盖按输出速率估算的一部分费用。长任务还会重复读取上下文、调用工具、创建子 Agent、执行测试并让人复核。社区一项飞行模拟器演示记录 Astra 约 28.55 美元，GPT-5.6 Sol 约 6.61 美元；但 Astra 使用 6 个子 Agent 和 ultra，Sol 使用单 Agent 和 high，作者也明确说明这不是同配置 Benchmark。
转折点Astra 真正值得关注的是长期工作的结构变化。OpenAI 表示，Codex 中的 Astra 可以跨上下文窗口保存笔记，并搜索此前没有进入摘要的需求、测试结果和工具输出；它还能在等待用户回答时继续处理不依赖答案的工作。跨窗口能力仍需配置启用，官方计划未来数周再设为默认。
为什么是现在当模型一次工作几十分钟、调用多个子 Agent 并直接操作软件，按单次提示或每小时输出量估价都会失真。更强模型可能单价更高，却因为少返工而降低任务成本；也可能因并行放大、缓存写入和验证不足让总账单上升。
对团队的启发建立固定任务账本：锁定模型版本、推理档位、Agent 数与工具；分别记录输入、缓存读写、输出、墙钟时间和人工时间；用测试、截图或结果回读判定成功；失败任务也计费。只有完成质量相近时，才比较每个通过任务的成本。

每百万输入 10 美元每百万输出 50 美元超过 200 亿 Token 的第三方测试量约 5.94 美元的一小时输出换算约 28.55 美元与 6.61 美元的非同配置演示

我的判断：“AI 工程师时薪”是好传播单位，却不是好采购单位。团队真正需要的指标是每个可验收任务的总成本，以及这笔成本换来了多少更少的等待、返工和风险。

Agent 没有时薪，只有完成一项工作前不断累积的任务账单。

来源：openai.com

📰 科技动态

1、npm 可信发布支持多套 OIDC 配置，稳定版与预发布不必再共用一条路径 official_ga_release

同一个 npm 包既要发 stable，也要发 prerelease；过去只有一套可信发布配置时，团队常被迫保留工作流绕行或长期 Token。

npm 现在允许每个包配置多套 OIDC 可信发布，并要求 staged package 完成恶意软件扫描后才能批准。

为什么重要：Web 与 Node.js 团队可按稳定版、预发布和 staging 拆开工作流；默认保留人工批准，直接发布只对必要配置开启。

事实边界：功能与正式可用状态由 GitHub 官方确认；它不能替代依赖审计、构建溯源和账号保护。

2、GitHub Actions 新增 Runner 退役 API 与只读漏洞告警权限 official_release

自托管 Runner 最难处理的不是升级本身，而是直到注册或运行被拒绝时才发现版本已经退役。

新 REST API 返回 Runner 停止注册与运行支持的时间；GITHUB_TOKEN 也新增只读 vulnerability-alerts 权限。

为什么重要：CI 平台可提前生成升级工单，并让扫描工作流只读 Dependabot 告警，不再借用更宽权限。

事实边界：接口字段和权限范围来自 GitHub 官方更新；仍需核对部署版本。

3、GitHub Copilot 将在 10 月 2 日停用一批模型，固定模型名的工作流需要迁移 official_announced_deprecation

Agent 工作流如果把模型名写死，模型退役就会从产品更新变成一次生产依赖迁移。

GitHub 宣布将在 2026 年 10 月 2 日跨 Copilot Chat、inline edits、ask、agent mode 与补全停用指定模型。

为什么重要：管理员应先确认替代模型策略，再用固定任务集比较行为、成本和权限请求；停用日期不代表今天已经不可用。

事实边界：日期、覆盖入口和管理员操作由 GitHub 官方确认。

4、Docker CLI 29.8.0 发布签名标签，但页面没有给出可用变更摘要 official_signed_release_tag_details_limited

版本号到了，不代表团队已经知道升级会改变什么。

Docker CLI 仓库出现 29.8.0 的已验证签名标签；本次证据页未返回完整变更说明。

为什么重要：将它视为版本信号而非升级建议：等待完整说明，并在 CI、BuildKit 与认证链路验证后再推广。

事实边界：发布标签与签名状态已确认；具体功能和兼容性证据不足。

🧩 本期概念库

1. 每个通过任务的成本

一句话解释：完整任务总费用除以通过统一验收的任务数。

为什么重要：它把失败、重试、并行和人工返工都纳入比较。

团队应用：固定任务集与验收标准，分别记录各模型总账单和通过数。

2. 跨上下文记忆

一句话解释：长会话填满窗口后，Agent 通过笔记和历史搜索找回早先需求、测试与工具结果。

为什么重要：它减少摘要遗漏，但也扩大需要治理的历史上下文。

团队应用：给笔记设置来源、时间和失效条件，关键决策回到原始证据。

3. 配置归一化

一句话解释：比较模型前固定推理档位、Agent 数、工具、时间预算和环境。

为什么重要：不同配置产生的成本差异不能直接归因于模型。

团队应用：基准记录完整参数，并把探索演示与正式对比拆开。

4. Staged Publishing

一句话解释：包先上传到等待区，通过扫描与人工批准后才对外发布。

为什么重要：它在 OIDC 工作流之后再增加一道供应链闸门。

团队应用：稳定版默认使用 staging，直接发布只对受控紧急流程开放。

5. Worktree 隔离

一句话解释：每个 Agent 使用独立 Git 工作目录与分支状态。

为什么重要：它防止并行任务直接覆盖同一文件状态。

团队应用：只并行低耦合任务，并在合并前统一跑集成测试。
